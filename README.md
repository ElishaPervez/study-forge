# Lesson Generator

Desktop tool that turns **one source unit** into **one self-contained HTML study guide**: one
PDF (the whole document or a single page range) or one ordered image group. Guides are
generated by OpenRouter under the bundled `diagram-design` design system, verified against
that system's own checker, and stored locally. The in-app UI brands this workflow as
*Study Forge*.

Everything is local-first and single-user: no accounts, no server, no telemetry. Sources and
generated artifacts live under `<checkout>/jobs/`, and the generated HTML opens with no
network access at all (fonts are embedded as base64 `@font-face` rules).

## Scope (v1)

- One PDF **or** one ordered image group per Forge action. PDFs and images never mix.
- Initial Forge takes **no user prompt**; the source is the whole brief.
- Every Forge action creates a history entry, including failures; a successful retry replaces
  the failed entry.
- Deliberately excluded: OCR, chat, settings screens, custom prompts, multiple providers,
  multi-range jobs, Codex ACP.

## Runtime shape

```
renderer (React 19, sandboxed)
  |  window.lessonGen  (contextBridge, desktop/src/preload.cts)
  v
Electron main (desktop/src/main.ts)
  |  spawns "uv run python -m backend.api" (stdio: stdout piped)
  v
backend/api/__main__.py  -> uvicorn on 127.0.0.1:0
  |  prints "LESSON_GEN_PORT=<port>" on stdout
  v
desktop/src/handshake.ts parses the line -> renderer builds http://127.0.0.1:<port>
  |
  v
FastAPI (backend/api/app.py) -> ingest -> generate -> verify -> persist
```

The window is frameless with `contextIsolation: true` and `nodeIntegration: false`; every
native capability (file picker, save dialog, window controls, backend lifecycle) crosses the
IPC bridge. On Windows the backend child tree is killed with `taskkill /T /F`, synchronously
on `process.on("exit")` as a final guard.

Pipeline: **ingest -> store or reuse the source copy -> extract one unit -> generate under
Diagram-design -> validate -> present/export.** The in-app preview and the exported file are
the same bytes from the same render path.

## Backend behaviour in detail

**Settings** (`backend/settings.py`) are split: `.env` supplies `OPENROUTER_API_KEY` (required;
its absence exits with code 2) plus optional `SKILL_DIR` (default `diagram-design`) and
`JOBS_DIR` (default `jobs`). The model, reasoning effort, and output cap are code constants,
not env-overridable: `meta/muse-spark-1.3-contributor`, effort `xhigh`, `max_tokens` 200000.
The OpenRouter provider is pinned to the model's namespace prefix with `allow_fallbacks: false`.

**Ingest** (`backend/ingest/`) stores sources under `jobs/sources/<64-hex>/`, addressed by the
content hash `sha256(kind, count, byte sizes, bytes)`. `store_source` validates the input shape,
reuses an existing copy, repairs a partially deleted one by re-copying differing files
(`filecmp.cmp(shallow=False)`), and migrates legacy manifests. Stored names are re-validated
against traversal on every read. PDF pages rasterise at 200 DPI (`ZOOM = 200/72`), are
downscaled to a 1536 px max edge, and cache as quality-82 JPEG keyed by page number; image
sources are normalised with the same constraints because original camera photos overflow the
provider's request-body limit. The viewer uses a separate `previews/` cache from the model's
`pages/` / `model-images/` cache.

**Generation loop** (`backend/generate/unit.py`) is the heart of the system:

- Budgets: `MAX_CALLS = 3` generation attempts and `MAX_TOOL_TURNS = 6` reference lookups,
  kept separate so the model cannot spend its whole allowance reading and never write.
  Retryable LLM errors back off exponentially between 0.1 s and 1.0 s.
- The model may call two tools, `list_references` and `read_reference`, limited to the skill's
  reference manifest; unknown names and malformed arguments become tool results, not failures.
- One repair attempt per run. An empty completion is reported as an empty completion
  (with `finish_reason` and reasoning-token counts) rather than as a policy violation against
  a document that was never written, and a reply truncated at the token ceiling is labelled
  as incomplete.
- Replies are sliced down to the document itself (`_strip_fences`), fonts are injected, and the
  artifact is written atomically *before* verification so a failed run still leaves its output
  inspectable (published artifacts are exposed only for `ok`).
- Statuses: `pending -> running -> verifying -> (repairing) -> ok | needs-attention | failed`;
  `needs-attention` means an artifact exists but a check failed.
- Guides left `pending/running/verifying/repairing` by a previous process are marked `failed`
  with a retry message on the next read (`recover_interrupted_guides`).

**Math** (`backend/mathml/render.py`) is rendered at build time, never at view time. The model
writes LaTeX between `\(...\)` (inline) and `\[...\]` (display), and generation rewrites those
delimiters into browser-native MathML before the artifact is verified, so nothing ships with
the file: no math library, no math web font, no network request. Only text is rewritten —
markup, attributes, and the contents of `script`/`style`/`svg`/`code`/`pre`/`math` are copied
through byte for byte, and an expression the converter cannot render stays as the author
wrote it instead of becoming malformed markup.

**Output policy** is enforced in code, not just in the prompt: a complete single `<html>`
document, no content outside it, no `<base>/<embed>/<object>/<iframe>`, no `on*` attributes or
`srcdoc`, no remote assets or stylesheets, no CSS `@import`, and the only permitted JavaScript
is a `<script data-guide-controls>` (or the canonical `data-diagram-controls`) block whose body
avoids `fetch`, `XMLHttpRequest`, `WebSocket`, `import`, `eval`, `Function`, `innerHTML`,
`insertAdjacentHTML`, `document.write`, string-to-code timers, `sendBeacon`, `document.cookie`,
and remote URLs. URL attributes are checked per scheme, with CSS escapes decoded first and
`data:image/*` (plus embedded `data:font/woff2` in CSS) allowlisted. `srcset` is parsed
candidate-by-candidate. The prompt (`backend/prompt/build.py`) states the same contract, and
the final gate is the skill's shipped `diagram-design/scripts/self_check.py`, run in a
subprocess (60 s timeout) with `  - finding` lines parsed back into structured findings.

**Persistence** uses atomic writes (temp file + `os.replace`) for every JSON record and
artifact. Guide metadata is `jobs/guides/<32-hex>/guide.json`; artifacts are
`.../artifact.html` plus per-unit `units/<unit_id>/artifact.html`. Guide ids are lowercase
32-hex, source ids 64-hex, and both are validated before any path is joined. History merges
current guides with read-only `legacy` entries discovered from pre-v1 `job.json` directories;
one malformed record never blocks the rest. A source copy is deleted when the last guide
referencing it is deleted, so deleting the user's original file never breaks a saved guide.

## HTTP API

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/api/sources` | Register a source from local paths (`{paths: [...]}`); classifies PDF vs images |
| GET | `/api/sources/{id}` | Source view plus per-file existence/size details |
| GET | `/api/sources/{id}/pages/{n}` | Rendered PDF page JPEG (PDF sources only) |
| GET | `/api/sources/{id}/images/{n}` | Stored image response (image sources only) |
| DELETE | `/api/sources/{id}` | Delete the stored source, or retain it when a guide still references it |
| POST | `/api/guides` | Create a guide for a source + selection |
| GET | `/api/guides` | History (guides newest-first, plus legacy entries) |
| GET | `/api/guides/{id}` | One guide with its source and `artifact_url` |
| POST | `/api/guides/{id}/generate` | Run generation (409 unless pending) |
| POST | `/api/guides/{id}/retry` | Re-run generation (409 unless failed/needs-attention) |
| POST | `/api/guides/{id}/revisions` | Revise a passage (`clarify` or `custom`) |
| PATCH | `/api/guides/{id}` | Rename |
| DELETE | `/api/guides/{id}` | Delete a guide (and its source when unreferenced) |
| GET | `/api/guides/{id}/artifact.html` | Serve the artifact inline, or as an attachment with `?download=1` |

Per-guide locks serialise generation, revision, rename, and delete; a separate lock guards
source registration/removal. Selection is `{mode: "all"}`, `{mode: "custom", start, end}` for
PDFs, or `{mode: "images"}`. Unreadable stored sources return a fixed recovery message (404)
so the UI can prompt for a re-pick instead of showing a raw parser error, and generation
failures are always persisted as guide state rather than lost with the request.

## Desktop app

`desktop/renderer/src/App.tsx` owns the workflow state machine (`workState`: registering,
removing, creating, generating, opening, renaming, retrying, deleting, revising, exporting;
any non-null value locks source controls). Notable behaviours:

- **Drop intake**: window-level file drops and the rail drop card both route through
  `classifySourcePaths` -> `handlePathsSelected`. In-app drags (page renders, image
  thumbnails) report a `Files` payload with no path, so `inAppDrag.ts` tracks `dragstart`/
  `dragend` and refuses them, preventing accidental window navigation.
- **Guide preview**: `GuideCard` fetches the artifact with `cache: no-store` and renders it in
  a `sandbox="allow-scripts allow-same-origin"` iframe via `srcDoc`, so what is shown and what
  is exported cannot diverge. Selecting text inside the frame opens `RevisionPopup`, positioned
  against live `getBoundingClientRect` measurements and retired by any click, collapsed
  selection, or scroll.
- **Export**: `exportGuideArtifact` fetches the same artifact URL, then saves through the native
  dialog; filenames are ASCII-folded, slugged, and prefixed when they collide with Windows
  reserved device names (`CON`, `LPT1`, ...). Revision ranges are appended as `-pages-a-b`.
- **Source viewer**: PDF pages and image thumbnails are served by the backend; right-clicking a
  page offers "set as first/last page" for the range selection.
- **History**: newest-first; a ready guide opens on plain click, failed ones expose Retry and
  Delete through a keyboard-navigable context menu (`Shift+F10` / context-menu key).

## Setup

Requires Python >= 3.12 with [uv](https://docs.astral.sh/uv/), Node with npm, and an OpenRouter
API key.

```bash
# 1. API key (required; no key = startup failure with exit code 2)
cp .env.example .env                            # then fill in OPENROUTER_API_KEY
                                                # optional: SKILL_DIR=diagram-design, JOBS_DIR=jobs

# 2. Backend alone (prints LESSON_GEN_PORT=<port>, then serves on 127.0.0.1)
uv run python -m backend.api

# 3. Desktop app
cd desktop
npm install
npm run build        # tsc (main, preload, renderer) + vite build
npm run dev          # build, then launch Electron
```

On Windows, `desktop/launch-interactive.ps1` starts Electron on `WinSta0\Default` via
`CreateProcess` so it appears on the interactive desktop; the script blocks on the process, so
run it in the background. Close the window to stop the backend; otherwise stop the Electron
main process with `taskkill //PID <pid> //T //F`.

> Guides and sources live in `<checkout>/jobs/`, so an app started from a different checkout or
> worktree shows an empty History.

## Tests and lint

```bash
uv run pytest -q            # 247 backend tests
uv run ruff check .         # line-length 100
cd desktop && npm test      # builds, then vitest (169 tests)
cd desktop && npm run build # tsc for main/preload/renderer, then vite bundle
```

Backend tests mirror the modules (`tests/api`, `tests/generate`, `tests/ingest`, `tests/jobs`,
`tests/llm`, `tests/prompt`, `tests/skill`, `tests/verify`, `tests/fonts`, `tests/mathml`) and drive the app
through `fastapi.testclient` with a scripted LLM and `httpx.MockTransport`, so no network or API
key is needed. Renderer tests cover the extracted pure helpers (placement, clamping, filename
sanitising, drop-session state, export flow) alongside component-render assertions.

## Conventions and limits

- **Never commit student material, extracted text, or generated artifacts.** `jobs/`, `*.pdf`,
  `.env`, `node_modules/`, `dist/`, plus the local-only `docs/`, `AGENTS.md`, `.freebuff/`,
  `.superpowers/`, and `.worktrees/` are gitignored. `backend/jobs/*.py` stays tracked.
- **Diagram-design is content, not styling.** The design system constrains every generated
  document; the prompt text and skill sources are versioned first-class artifacts. The first-run
  style-guide gate in `SKILL.md` is stripped when the bundle is loaded, because the app has
  already resolved the style guide.
- Prompts and policy live in `backend/prompt/build.py`; behaviour changes belong there and in
  `backend/generate/unit.py`, not in the renderer.
- Undecided product surface (accounts, packaging) is intentionally absent; ask before assuming.
