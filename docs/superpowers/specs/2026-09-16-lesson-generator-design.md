# Lesson Generator — Design

**Date:** 2026-09-16
**Status:** approved design, pre-implementation

## 1. Goal

A Windows-only local desktop app. The student picks a scanned PDF, marks page ranges
as units, clicks **Generate**, and gets one self-contained HTML study artifact per
unit, generated by a model under the vendored `diagram-design` skill. The user never
sees or manages model calls.

### Non-goals for v1

OCR of any kind. Accounts, sync, hosted backend. Job history beyond the jobs folder.
A render/install pipeline for the school laptop. Per-job skin selection. Image-group
ingest (loose photos). Bundling units into an index page. Motion/animation in output.
Automated geometry checks beyond `self_check.py`.

## 2. Architecture

Two processes on one machine.

**Electron main process** (`desktop/`): owns the window, native file dialogs, and the
backend lifecycle. It spawns the backend once, reads the port it announces, and
exposes that port to the renderer through preload.

**Python backend** (`backend/`): FastAPI on `uvicorn`, bound to `127.0.0.1` on an
**ephemeral port** (port `0`), which it prints to stdout as a single machine-readable
line on startup. It owns ingest, prompt assembly, model calls, verification, and
artifact storage.

**Transport:** plain HTTP from the renderer to `127.0.0.1:<port>`. No per-call IPC,
no stdio protocol, no custom message bus.

**Lifecycle rules:** the child is killed on `before-quit` *and* on main-process exit;
a pidfile in the app data directory lets a new session reap an orphan holding the
port. The renderer never learns a port it did not receive from preload.

**Why two processes:** the skill's validator is Python (`self_check.py`, stdlib only),
so Python is already load-bearing. Keeping it also keeps `pymupdf` for page rastering
rather than hand-rolling PDF extraction in JS.

## 3. Data flow

```
PDF file (unchanged, never copied into the repo)
  -> render each selected page, <=1536px long edge, JPEG q=82   -> jobs/<id>/pages/
  -> units: named, 1-based inclusive page ranges                -> jobs/<id>/job.json
  -> per unit: prompt assembly + tool loop + repair             -> model
  -> self_check.py                                              -> exit 0/1
  -> jobs/<id>/units/<uid>/artifact.html                        -> preview + download
```

Units are independent. One unit failing never blocks or aborts the others, and a job
that produces some artifacts is a success, not an error.

## 4. Components

| Module | Responsibility | Depends on |
|---|---|---|
| `backend/skill/manifest.py` | Build the closed set of reference names from disk at startup | skill dir |
| `backend/skill/bundle.py` | Read `SKILL.md`, `style-guide.md`, one ref by name | manifest |
| `backend/prompt/build.py` | Assemble the stable prefix and the unit message | bundle |
| `backend/fonts/embed.py` | Inject `@font-face` blocks with base64 woff2 | font assets |
| `backend/ingest/pdf.py` | Page ranges -> downscaled JPEGs | pymupdf, pillow |
| `backend/llm/client.py` | OpenRouter call, error mapping, usage capture | httpx |
| `backend/generate/unit.py` | Tool loop, repair pass, unit status | client, bundle, verify |
| `backend/verify/self_check.py` | Run the skill's checker, parse findings | subprocess |
| `backend/jobs/store.py` | Job/unit layout, atomic writes, path safety | filesystem |
| `backend/api/app.py` | FastAPI endpoints | all of the above |
| `desktop/main.ts` | Spawn backend, port handshake, lifecycle | node, electron |
| `desktop/renderer/` | UI: picker, thumbnails, range editor, status, preview | React, Tailwind |

Each module is testable without the others. `generate/unit.py` takes an injected
client, so the whole loop is testable against a fake with no network.

## 5. Generation contract

Per unit, one agent loop. The user sees one button and one progress state.

**Prompt order is stable → variable → task**, because OpenRouter prompt caching is
prefix-based: the skill bundle becomes a cross-unit cache hit, while page images
(correctly) sit outside the cached prefix.

1. **System (stable, cached):** SKILL.md core + `style-guide.md`. The §0 first-time
   style-guide gate is **omitted by construction** — the app has already decided, so
   there is nothing to ask.
2. **Tools:** `list_references()` returns the manifest's names with one-line
   descriptions; `read_reference(name)` returns one reference; `read_example(type)`
   returns a matching `assets/example-*.html` as a style anchor.
3. **Message:** the unit's page images, then the unit instruction.
4. The model reads what it needs, then emits the artifact HTML as **raw text** — no
   JSON wrapper, because escaping 30 KB of markup through a JSON string is a needless
   failure mode.
5. **Caps:** at most **3 model calls per unit, total.** A call may contain tool rounds
   (reference reads); the loop ends when the model emits the artifact. Verification
   runs after the artifact call. If it fails and the unit has calls left in its
   budget, the model gets one repair call. If it fails with the budget exhausted,
   the unit is `needs-attention`. Three is a ceiling, not a target — a unit that
   needs no references finishes in one call.

**Parameters:** model pinned to the dated slug `deepseek/deepseek-v4.1-flash-20260910`
(the `~deepseek/deepseek-flash-latest` alias follows the family and silently changes
behaviour), `reasoning_effort: "low"` (reasoning is on by default at `high`, which
costs latency for no gain here), output capped at 32768 tokens.

**Security:** reference names are validated against the manifest built at startup. The
model can only name a member of that closed set; it can never supply a path. Page
images are untrusted input and may contain text attempting to redirect the model, so
skill content and page content are never concatenated into one instruction channel.

## 6. Output contract

**Fonts.** Instrument Serif, Geist, and Geist Mono, Latin subsets, embedded as base64
woff2 inside **one inline `<style>`** via `@font-face`. The Google Fonts `<link>` is
dropped. This is not a stylistic choice — it is the only shape that passes the
checker:

- `reference_error()` rejects any `data:` URL that is not `data:image/`, so a
  `<link href="data:font/woff2;base64,…">` **fails**.
- References are only collected from HTML tag attributes; CSS inside `<style>` is
  captured as text and never scanned, so `@font-face` with a `data:font/woff2` source
  passes.

**Scripts.** v1 emits no `<script>` and no motion markup. `check_motion()` early-returns
when no motion markup is present, so static output passes for free. Any script is only
legal if its body byte-matches the canonical controller in `assets/template-motion.html`
and carries exactly one `data-diagram-controls` attribute — not worth the failure mode.

**Also enforced by the checker:** every non-decorative SVG needs `role="img"`, `<title>`
as its first child, non-empty `<title>` and `<desc>`, IDs prefixed with the diagram slug
(never bare `title`/`desc`), and `aria-labelledby` naming the title ID then the desc ID
in that order. `<base>`, `<embed>`, `<object>`, `<iframe>`, all `on*` attributes, and
`srcdoc` are banned outright.

**One render path.** The backend writes `jobs/<id>/units/<uid>/artifact.html` exactly
once. The in-app preview is an `<iframe>` pointing at
`GET /jobs/{id}/units/{uid}/artifact.html`; the download button hits the same URL with
`Content-Disposition: attachment`. Same bytes, one file — the in-app view cannot
diverge from the download.

## 7. Verification

`backend/verify/self_check.py` runs the skill's shipped checker as a subprocess:

```
python <skill>/scripts/self_check.py <artifact>
```

Contract, verified from source: exit `0` means every file passed; exit `1` means at
least one failed. stdout is `OK <path>` or `FAIL <path>` followed by `  - <finding>`
lines. It has no third-party dependencies, so it runs under the same interpreter as
the backend.

**Repair loop:** on failure, the checker's findings are appended to the conversation
and the model gets one repair call, subject to the 3-call budget in §5. A failure
with no budget left marks the unit `needs-attention` and preserves the failing HTML
for inspection. It never blocks sibling units.

**Known gap:** SKILL.md §9 references `scripts/verify-geometry.py` and
`scripts/verify-motion.py`, which do not exist in this checkout. v1's automated gate
is therefore `self_check.py` only. This is recorded, not silently papered over.

## 8. Storage and what is never committed

Filesystem only, no database:

```
jobs/<job_id>/job.json              # source path, units, status
jobs/<job_id>/pages/<n>.jpg         # downscaled rasters
jobs/<job_id>/units/<uid>/meta.json # status, requested refs, usage
jobs/<job_id>/units/<uid>/artifact.html
```

Writes are atomic (temp file, then replace) so an interrupted run cannot leave a
half-written artifact that the UI would happily serve.

**Never committed:** student material, rasterized pages, `job.json`, or generated
artifacts. `jobs/` is gitignored in full, and source PDFs are referenced in place
rather than copied into the repo. `.env` holds `OPENROUTER_API_KEY` and is gitignored.
`.gitignore` also covers `.venv/`, `node_modules/`, `dist/`, and `__pycache__/`.

## 9. Error handling and partial success

- **In-progress:** each unit reports `pending | running | verifying | repairing | ok |
  needs-attention | failed`. The UI shows the units, and generation is per unit so a
  slow unit does not stall the view.
- **Partial success is normal.** A job finishes when its units finish; some being
  `needs-attention` is an expected outcome, and the UI reports it as such rather than
  as an error.
- **Retry is per unit.** Re-running one unit never re-runs its siblings and never
  re-rasterizes the PDF.
- **Transient vs permanent:** HTTP 429/5xx and timeouts are retried with backoff;
  a malformed model response is not retried blindly but is repaired once. Auth and
  quota failures surface as a job-level error, because retrying them cannot help.
- **Missing API key** fails fast at startup with a clear message rather than at the
  first generation.

## 10. Testing strategy

TDD throughout; each task's deliverable is independently testable.

- **Backend unit tests (pytest):** the manifest's closed set and rejection of path-like
  names; prompt ordering and the absence of the §0 gate and the Google Fonts link;
  font embedding shape; raster downscaling bounds; checker exit-code parsing; job
  layout and atomic writes.
- **The model is faked.** `llm/client.py` sits behind a protocol, and the generation
  loop is tested against a fake that (a) requests a reference, (b) emits a first
  artifact that fails the checker, then (c) emits a fixed one — asserting the run
  stayed within the 3-call budget, that exactly one repair call happened, and that
  the unit ends `ok`. A second fixture exhausts the budget and asserts the unit ends
  `needs-attention` with its failing HTML preserved.
- **The checker is the oracle.** Tests call the real `self_check.py` on a real shipped
  `assets/template.html` (expect exit 0) and on a deliberately mutated copy (expect
  exit 1). This keeps our understanding of the checker honest instead of assumed.
- **Fixture PDF:** built in the test, not committed, so no student material and no
  binary fixture enters git.
- **Renderer/desktop:** the port-handshake parser is unit tested in Node. UI logic
  stays thin on purpose; there is no browser-test harness in v1.

## 11. Decision record

| Decision | Choice | Why |
|---|---|---|
| App shape | Local Electron + Python, Windows-only | Desktop requested; Python already required by the skill's checker |
| Transport | HTTP to an ephemeral localhost port | Avoids per-call IPC and a custom protocol |
| OCR | None | The model accepts images (`text+image->text`), so OCR adds latency and error for nothing |
| Page input | Single scanned PDF, ordered pages | Simplest ingest; ranges are just page numbers |
| Orchestration | One button, model-directed tool loop, 1–3 calls | User requirement: no visible multi-step |
| Skill injection | Closed manifest + `read_reference` tools | Respects the skill's own progressive-disclosure design; avoids attention dilution |
| Model | `deepseek/deepseek-v4.1-flash-20260910`, `reasoning_effort: low` | Vision input, 1M context, $0.15/$0.60 per M, 50× cheaper cached reads |
| Fonts | Base64 woff2 via `@font-face` in inline `<style>` | Only shape that is both self-contained and checker-clean |
| Skin | Shipped default, resolved from the working copy | Decided once; the §0 gate is omitted by construction |
| Style-guide marker | **Not written** | `profile: default` requires `~/.diagram-design/profiles/default.md`; a marker naming a missing profile is a hard error, not a fallback |
| Packaging | Deferred | The laptop move does not require an installer for v1 |

## 12. Deferred

PyInstaller/installer for the school laptop. Image-group ingest. Geometry and motion
verifiers. Per-unit cost ceiling enforcement. Unit bundling into an index page.
Parallel unit generation. A skin picker. Motion support.
